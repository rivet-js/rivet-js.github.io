Accessibility

Keep the platform's
native semantics.

Rivet renders ordinary DOM and deliberately leaves keyboard behaviour, semantics, focus, validation, labels and platform controls in the browser's hands.

Semantic HTML first

Use the same semantic elements you would without Rivet. Buttons remain buttons, links remain links, labels remain labels, and ARIA remains ordinary markup.

html`
  <label for="name">Name</label>
  <input id="name" name="name" required>
  <button type="submit">Save</button>
`;

Focus and keyboard behaviour

Rivet does not invent keyboard behaviour for native controls and does not move focus just because reactive output changed. When application logic needs focus, use a normal DOM ref and element.focus().

Forms and validation

Native events, FormData, browser validation, labels and requestSubmit() continue to work. Hypermedia forms should retain meaningful action/method fallbacks so the underlying HTML remains useful without JavaScript.

Platform controls

Use native APIs such as <dialog> and showModal() directly. Rivet does not add wrapper abstractions around browser controls.

Application responsibility

Rivet cannot make inaccessible markup accessible. Applications still own semantic structure, accessible names, contrast, focus strategy for custom widgets, async announcements where needed, and assistive-technology testing.
