Hypermedia

Server HTML.
Explicitly placed.

Rivet's optional hypermedia layer is intentionally narrow: native fetch semantics, HTML responses, explicit targets, explicit swaps, and native lifecycle events.

Why it exists

For fragment loading, normal form submissions, pagination, and inline edits, request + target + swap is repetitive boilerplate in vanilla JavaScript. Rivet will make that common path concise without taking ownership of routing, history, polling, confirmation logic, or application state.

Programmatic first

const result = await request("/users");
// result.response
// result.html

The JavaScript API is the engine. Declarative r-* attributes are thin syntax over the same behaviour.

Still optional

If plain fetch() is clearer for a feature, use it. Hypermedia support does not sit underneath Rivet's reactive core and is not required for components.

request()

const { response, html } = await request("/users", {
    method: "POST",
    body: new FormData(form),
    signal: controller.signal
});

request() forwards native fetch options, reads the response as HTML text, and throws RequestError for non-success HTTP responses. Network and cancellation errors remain native fetch errors.

Targets and swaps

await request("/users", {
    target: "#results",
    swap: "inner"
});

swap("#notice", "<strong>Saved</strong>", "outer");

The first swap set is deliberately small: inner, outer, before, and after. Server HTML can be placed programmatically without a declarative layer.

Native lifecycle events

results.addEventListener("rivet:after-swap", (event) => {
    console.log(event.detail.nodes);
});

Rivet emits native bubbling CustomEvents: rivet:before-request, rivet:after-request, rivet:request-error, rivet:before-swap, and rivet:after-swap. There is no plugin-specific event bus.

Declarative requests

<button
    r-get="/users"
    r-target="#results"
    r-swap="inner">
    Load users
</button>

Call enhance() on a DOM root to activate r-get and r-post. r-target selects the swap target, r-swap accepts the same four swap modes as swap(), and r-trigger may be click, input, change, or submit. Rivet intentionally does not provide a trigger mini-language.

const stop = enhance(document);
// later
stop();

Progressive forms

<form action="/search" method="get" r-get="/search" r-target="#results">
    <input name="q">
    <button>Search</button>
</form>

Keep normal action, method, labels, validation, and controls as the non-JavaScript fallback. Once enhanced, GET forms encode native FormData into the query string; POST forms send the native FormData body. Rivet does not introduce a forms model.

History stays browser-owned

Rivet deliberately does not ship partial-navigation/history attributes yet. Correct navigation immediately raises policy for pushState, popstate, scroll restoration, focus, titles, redirects, failures, and caching. Use ordinary links, the native History API, or a dedicated router when navigation is genuinely application architecture.

Reactivity interoperability

Swaps dispose Rivet-owned bindings in DOM they remove. Inserted server HTML remains ordinary DOM: Rivet does not secretly mount components or execute returned scripts. If a swapped fragment contains new r-* attributes, call enhance(root) again (often from rivet:after-swap). Re-enhancement is idempotent and will not double-bind existing elements.
