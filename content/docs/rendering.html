Rendering

HTML stays HTML.

Rivet uses a tagged template and updates the DOM nodes tied to reactive values rather than requiring a virtual DOM.

Templates

const view = html`<p>Hello ${name}</p>`;
const fragment = render(view);

Text interpolation is escaped by the DOM. State cells and zero-argument functions create reactive text bindings.

Attributes and properties

html`<div title=${title}>...</div>`
html`<input .value=${name}>`

Normal names bind attributes. A leading dot explicitly binds a native DOM property.

Events

html`<button onclick=${save}>Save</button>`

Event handlers are native functions attached with addEventListener.

Nodes and nested templates

const icon = document.createElement("span");
const child = html`<strong>Rivet</strong>`;

html`<p>${icon} ${child}</p>`

Native DOM nodes and Rivet template results can be interpolated directly. A reactive cell or expression may replace that DOM region without rerendering the surrounding template.

Cleanup follows the rendered subtree

Reactive bindings and Rivet-owned event listeners are attached to the DOM nodes they serve. When Rivet replaces a rendered subtree, those resources are disposed before the old nodes are released.

mount(target, template)

const unmount = mount("#counter", Counter());

// Later:
unmount();

mount() renders into one existing element or selector and returns a cleanup function. Rivet does not need to own the rest of the document.

Refs stay native

html`<button ref=${node => { button = node; }}>Run</button>`

The callback receives the actual element, not a Rivet wrapper. Rivet calls the callback with null during disposal so stale references can be cleared.

Conditions are JavaScript

html`${() => ready.value
    ? html`<p>Ready</p>`
    : html`<p>Waiting</p>`}`

Rivet does not add an if directive. Use normal ternaries, &&, functions, and other JavaScript expressions. A function interpolation is reactive when it reads reactive cells.

Lists use arrays

html`<ul>${items.map(item =>
    html`<li>${item.name}</li>`
)}</ul>`

Arrays are renderable, so ordinary map(), filter(), and other JavaScript collection operations remain the list syntax.

Preserve identity only when you need it

html`<ul>${() => rows.value.map(row =>
    key(row.id, html`<li>${row.label}</li>`)
)}</ul>`

key(id, value) preserves the already-rendered DOM for a key when a reactive list reorders. Every item in a keyed list must use key(); duplicate keys are errors. Because an existing keyed region is preserved rather than rerendered, values that must change in-place should themselves be reactive.

Forms stay native

html`<form onsubmit=${save}>
    <input name="name" .value=${name}
        oninput=${event => { name.value = event.currentTarget.value; }}>
    <input type="checkbox" .checked=${accepted}>
</form>`

Use normal input/change/submit events, explicit DOM property bindings, browser validation, and FormData. Rivet intentionally does not ship a separate forms model.

Classes and styles are attributes

html`<div
    class=${() => active.value ? "card active" : "card"}
    style=${() => `width:${width.value}px`}
>...</div>`

Ordinary dynamic attributes cover the current class/style use cases, so Rivet does not add class-map or style-object helpers.
