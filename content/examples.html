Async interaction

Use the platform

const status = state("Idle");
let activeRequest;

async function load() {
    activeRequest?.abort();
    activeRequest = new AbortController();
    status.value = "Loading…";

    try {
        const response = await fetch("/data", { signal: activeRequest.signal });
        if (!response.ok) throw new Error(`Request failed (${response.status})`);
        status.value = "Ready";
    } catch (error) {
        if (error.name !== "AbortError") status.value = "Error";
    }
}

Rivet does not need an async abstraction for ordinary loading, errors, cancellation, or fetch. Reactive cells hold UI state while JavaScript does the work.

Stress example

Editable data without an application framework

const filter = state("");
const sortAscending = state(true);

function visibleRows() {
    return rows
        .filter(row => row.name.value.includes(filter.value))
        .toSorted((a, b) => sortAscending.value
            ? a.name.value.localeCompare(b.name.value)
            : b.name.value.localeCompare(a.name.value))
        .map(row => key(row.id, Row(row)));
}

The stress fixture combines filtering, sorting, selection, inline editing, validation, keyed identity, and async save state. It still uses ordinary JavaScript data flow and browser events.

Hypermedia

Server HTML without an SPA

<form action="/search" method="get"
      r-get="/search"
      r-target="#results">
    <input name="q">
    <button>Search</button>
</form>
<div id="results"></div>

<script type="module">
    import { enhance } from "rivet";
    enhance(document);
</script>

The form remains a normal form without JavaScript. With Rivet enabled, it requests server-rendered HTML and swaps only the target.
